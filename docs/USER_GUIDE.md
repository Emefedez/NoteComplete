# User guide

## Open and navigate

Choose **Open document** in the hamburger menu or drop a `.noteful`, `.nfedit`, PDF, PNG, JPEG or WebP file into the reader. HTML pages, text and Markdown files open in their own view; so do Word (`.docx`), OpenDocument (`.odt`, `.ods`), Excel (`.xlsx`), CSV and TSV files, shown as Markdown and read-only (see [Office files](#office-files)). PDF pages scroll continuously; the Pages panel shows previews. The UI is English; note content, saved layer names and recording names retain their original text. Pages scroll continuously and only nearby pages render. **Page** jumps to a page. **Fit** adapts its width; **− / +** change zoom by ten percentage points, from 10% to 400%.

The toolbar compacts when scrolling down and returns when scrolling up. Its arrow provides a manual override. On phones, compact mode keeps playback and seeking available while hiding secondary controls. In a narrow window or on a phone, the menus, the tools and the page row scroll sideways when they do not fit (swipe, or use the mouse wheel over them); a faded edge shows there is more. The phone page row keeps dark pages and **Fit**; the zoom steps are in **View**. A phone held sideways (a window under 500 px high) puts the page row and the tools on one row, tools as icons, and opens the page list as a drawer. **View → Tool bar** (or the page row's tool bar button) moves the page row and the tools to columns on the left or right instead, on a computer too.

New keys: **Shift P** page list, **Shift G** go to page, **Shift I** insert image, **Shift B** insert blank page, **Shift O** recognize text (OCR), **Shift E** export flashcards and quizzes to Anki, **Shift U** lift all tape / cover it again, **Shift X** insert graph, **Shift Y** insert table. Press **?** (outside a text box) to show each button's key on the button itself; press it again to hide them. **Help → Keyboard shortcuts** lists every key, Ctrl ones included. The moon next to **Pages** (**D**) is a night view: white paper turns black and dark ink light, colours keep their hue (red ink stays red), also in the page previews and while drawing. It only changes the display. The three buttons beside the zoom place the pages on the left, in the middle or on the right when they are narrower than the window; the button next to them leaves the pages wherever you scroll them. **Ctrl+F** opens Find and closes it again. Choosing a tool opens its settings under it; press the tool again to hide or show them. **View → Auto-open tool settings** turns the automatic opening off; the arrow at the end of the toolbar hides or shows the settings too. The floppy disk beside the note title shows whether the project is saved: a dot means unsaved changes, and clicking it saves (**Ctrl S**).

### Office files

Word (`.docx`), OpenDocument (`.odt`, `.ods`), Excel (`.xlsx`), CSV and TSV files open as Markdown in the text view, to read: headings, paragraphs, lists, tables, links, bold, italic and footnotes come through; page layout and pictures do not. A spreadsheet shows one heading per sheet and its cells as a table, as formatted in the file, up to 1000 rows and 50 columns a sheet (a line under the table says when it was cut). In a CSV file the first row is the header; fields separated by `;` are recognized too. Find (**Ctrl F**), the study tools and **MD** work as for a `.md` file. There is no **Edit**: the floppy disk (**Ctrl S**) saves a `.md` copy of what you see, and **File → New from Markdown…** starts from it to write it as handwriting. The original file is never changed. The Word and spreadsheet readers are downloaded the first time you open such a file and kept for offline use.

### Opening files from the system

NoteComplete appears in the system's **Open with** menu for the files it reads: its own `.noteful`, `.nfedit`, `.notecomp` and `.notepart`, and PDF, PNG, JPEG, WebP, Markdown, text, HTML, Word (`.docx`), OpenDocument (`.odt`, `.ods`), Excel (`.xlsx`), CSV and TSV files. It is the default app only for its own formats; for PDFs, images, text and Office files it is offered, and your default stays as it was. Audio files are not opened this way: add a recording from a note's audio panel.

- **Windows, macOS and Linux (desktop app):** double-click a NoteComplete file, or right-click any supported file and choose **Open with → NoteComplete**. With the app already open, the file opens in a new tab of the front window. Files opened this way join Recent, and an edited text file saves back to its place. On Linux the AppImage registers these types only when it is integrated into the desktop (for example with AppImageLauncher or Gear Lever).
- **Android:** choose **Open with → NoteComplete** in Files or another app, or **Share → NoteComplete**. The file keeps its name and extension, so a Word file opens as Word and a PDF as a PDF. Android decides whether to offer **Always**.
- **Installed web app (Chrome, Edge or ChromeOS):** after **Help → Add this site as an app…**, the browser lists NoteComplete under **Open with** for the same types; each file opens in a window of its own. On ChromeOS and Android, **Share → NoteComplete** works too.
- **iPhone and iPad:** there is no native app, so NoteComplete cannot appear in **Open in…**. Open files from Safari's NoteComplete (or the Home Screen web app) with **Open document**.

## Study with your AI tool

Study and Ask AI use an AI tool already installed and signed in on your computer (Claude Code, Antigravity, Codex or OpenCode) and run in the desktop app. Pages are sent as images with tape lifted, together with their typed, PDF, recognized and transcript text.

- **Study → Generate quiz (AI) (Shift+Q)** generates multiple-choice questions in the background; the chip in the bar shows progress and has Stop. Quizzes are saved with the note: **Q** resumes the latest, **Study → Saved decks and quizzes (Shift+D)** lists them, **Retake wrong answers (Shift+W)** gathers misses from all of them. In the quiz: 1–4 answer (a question marked *choose all that apply* has boxes: toggle the right ones with 1–9, then **Enter** or **Check answer**; it scores only if the whole set is right), **H** shows the region of your notes that answers it (a correct answer is then worth 1 point instead of 2), **C** asks the AI to clarify, **X** twice disputes a question that is wrong, **V** asks the AI to double check and lets you save the correct answer yourself, **Enter** next, **M** minimizes. **Edit quiz instructions…** changes what the AI is asked for.
- **Study → Generate flashcards (Shift+C)** makes a deck shown as cards, question over answer. Click a card to edit it in place (Esc or Ctrl+Enter to finish); the page badge shows its page and ✕ deletes it. Lists the AI writes on one line ("1) … 2) …") are put one item per line. **Practise** flips cards in a fixed-size card: **Space** shows the answer, **1** not yet, **2** I knew it. **Export to Anki…** keeps line breaks.
- **Study → Fact check… (Shift+F)** has the AI read the current page, a range or the whole note, and report per page what is wrong (dates, definitions, formulas, numbers, calculations), inconsistent (on the page, or with another page of the check: each batch of pages gets the text of the others to compare), unclear or missing, each with a correction. It runs in the background like a quiz; when it ends, its findings are added at the end of your Markdown notes under a heading with the date, each page's under that page's badge (click it to go to the page), and the pages with nothing to correct in one line. **Open notes** on the finished job shows them. They are suggestions: check them against your sources. Text documents are checked by section.
- **Ask AI (Ctrl+J)** answers questions about the page, a selected item, or a region grabbed with the **Grab** tool (**G**). Under a grabbed region, icons select what is inside, copy its text, ask AI, add it to the chat, or **erase** the ink in it (one undo brings it back).
- **The windows** (Ask AI, quizzes, flashcard practice, audio) move by their title bar and resize from any edge or corner. As in a tiling window manager, you can also grab them anywhere: hold **Ctrl** (**⌘** on a Mac) and drag to move a window, or hold **Ctrl** and drag with the **right** mouse button to resize it from the corner nearest the pointer. Text fields keep their own clicks. Place and size are remembered.
- **Help → Connect AI tools…** lets those tools work with your notes outside the app too (summary pages written in handwriting, clean copies, grading a quiz, flashcards). NoteComplete comes with the note server they use; **Connect** registers it with each installed tool, and *Run it yourself* shows the command instead. The desktop app offers this once by itself when it finds a tool that is not connected. Restart the tool afterwards. See [AI agents](MCP.md).

### AI in the app, without installing anything

In a browser with WebGPU (recent Chrome or Edge, Safari 26) the website has AI too: the tool list shows **In this app (WebLLM)**, and in the desktop app it appears after your own AI tools. It runs a model on your graphics card, so your notes never leave the device. See [AI in the app](LOCAL-AI.md) for the details.

- **Your handwriting is read by the app's own text recognition** (as in Find → Recognize handwriting), page by page as it is needed, and kept with the note, so later searches find it too. The default model, Qwen3 1.7B, is a 1 GB download; Qwen3 0.6B (0.3 GB) suits phones and older devices, Qwen3 4B (2.3 GB) gives better answers on laptops with a strong graphics card. **Phi 3.5 Vision** (2.8 GB) looks at the page image itself, for diagrams and pages recognition cannot read; on handwriting it was less accurate and much slower in our tests. The model list says "reads pages" or "text only", and a **Text only** badge appears beside it.
- The first use downloads the model once. The chip in the bar shows the download; **Stop** ends it, and what was downloaded is kept for next time. After that it works offline. **Downloaded models…** (the gear beside the model list) shows what is kept and deletes it.
- **One page at a time** (formerly *Small model*), beside every model list, splits the work into small steps: each page's text is taken on its own (its handwriting recognized first), flashcards, questions or corrections are made from that page alone, and the results are merged with duplicates removed. Each quiz question quotes the page, and its hint (**H**) outlines where those words are. It is on for the model in this app and off for Claude Code, Codex and the other tools, which do better seeing several pages at once; you can change it either way, and the choice is kept per tool. The chip shows which page is being read or worked on; a page that fails is skipped and the rest kept.
- A model stays loaded while you use it and is unloaded after three minutes without requests, to free memory; the next request loads it again in a few seconds.
- Answers are simpler, and sometimes wrong, compared with Claude Code or Codex, and a misread word becomes a wrong card: check them.
- Without WebGPU (Firefox on Linux, older browsers and phones) the AI commands say so.

## Tape and locked items

Tape (Noteful's *Cinta*) hides parts of a page, typically answers. In Pan mode, tap a tape to lift it and tap again to cover; **View → Lift all tape / Cover with all tape / Tape as saved** applies to the whole note. Tape state is a viewing choice and is not saved. Items locked in place in Noteful cannot be selected, moved or erased. Zoom with <kbd>Ctrl</kbd>+<kbd>+</kbd> / <kbd>−</kbd>, and <kbd>Ctrl</kbd>+<kbd>0</kbd> fits the page; this works on any keyboard layout.

## Infinite canvas

**File → New document… → Canvas** makes one page that grows as you write. When ink, a picture or a text box comes near its right or bottom edge, the page gets bigger, and the view stays where it is. Undo removes the stroke first and then the growth. A canvas is saved as a NoteComplete project (`.nfedit`), and can be exported as `.notecomp`. It is never a `.noteful` file, because Noteful has no infinite page: the Noteful format and the NF exports are off for it. Pages cannot be inserted into a canvas. PDF, SVG and image exports show it as one large page.

## Insert pages

Scroll past the last page and **New page** adds a blank page the size of the last one (one Undo takes it away).

**Pages → Insert blank page…** adds white pages after or before the current page, or at the end: the same size as the current page, A4 or Letter in either orientation, 4:3 or 16:9 slides, or a custom size in millimetres. **Pages → Insert PDF pages…** adds a range of pages from another PDF at the note's own scale; *Extra writing space* makes those pages wider (or taller) with blank paper beside the PDF, like widened pages in Noteful. Each insertion is one undo step, and ink drawn earlier stays on its page. Inserted pages are kept in the project and in native `.noteful` exports (experimental, like all native export).

## Diagrams: the UML editor and PlantUML files

UML prefabs (Insert prefab → UML …) open the UML editor. Its palette lists the diagram's elements and connectors (keys 1–9, Shift S for a ring at the pointer). Point at an element and drag its arrow handle to another one to connect them; hold Shift when letting go to choose the kind and direction. Drag a line to bend it, drag the hollow dot in a stretch for another bend, and drag a selected line's end onto another element to reconnect it. Right-click (or hold) opens each item's menu: type, the head at each end of a line and whether it is solid or dashed, swap direction, straighten, make rectilinear, colour and text size. The round **?** opens a cheat sheet of every gesture and key; it floats and can be moved, resized or put away.

Any text you write can be **bold**, *italic* or underlined: the **B / I / U** buttons in the properties sit beside the name of an element (class, actor, use case, state, action, note…), beside each attribute, operation, literal or action line (one row of buttons per line, under the list), beside a line's label, and beside what each end of a line shows. Ctrl B, Ctrl I and Ctrl U do the same while typing in that field, in the list (for the lines the cursor is on) or in the box that renames on the canvas. Abstract classes and operations, and interfaces, are always italic: their italic button stays on. A named association, dependency or arrow can **Show direction**: UML's small filled triangle beside the name, pointing along the line toward its end or its start. Every relation line can also carry free text at its start and at its end (**Text** in the properties, under the multiplicity on the drawing); drag that text to place it, and right-click → *End texts back by their ends* to undo that. In PlantUML the styles are written as Creole (`//italic//`, `**bold**`, `<u>underline</u>`), the direction as `: name >` or `: < name`, and the end texts in the quotes at each end (`A "1\nowner" -- "items" B`); XMI keeps them in NoteComplete's own section, Visual Paradigm XML has no place for them.

The **Visual / Code / Both** buttons switch between the drawing and its PlantUML text, which edit each other. A new class or use case diagram asks which of the three to start with, unless **Ask every time** is off. Import reads Visual Paradigm XML, XMI, PlantUML and NoteComplete files; Export writes them, as well as SVG and PNG pictures.

**Workspace tabs.** As in Visual Paradigm, several diagrams can be open at once, each in a tab above the editor. **+** starts a new diagram of any kind in a new tab; the arrow beside it lists the note's other UML diagrams (with their page) and opens one in a tab. Click a tab, or press **Ctrl Page Up / Page Down**, to switch; each tab keeps its own undo, selection and zoom. A dot marks a tab with changes. Closing a tab (its ×, or a middle click) keeps its changes. **Apply** redraws every changed diagram where it is and puts new ones on the page of the diagram you opened (each is its own undo step); **Cancel** drops them all. *Show in…* on an element of another UML diagram opens that diagram in a tab, with the element selected. The tabs you had open come back the next time you edit a diagram of the same note. On the editor's own page (**UML diagram editor…**) the tabs are its drafts, kept in this browser; a closed one is in the arrow's list.

PlantUML files (`.puml`, `.plantuml`, `.pu`, `.iuml`, `.wsd`) open like text documents. Class, package and use case diagrams open in the UML editor, and every change is written back as PlantUML; save it with Ctrl S. The positions of the boxes are kept in a `' notecomplete-layout` comment, which PlantUML ignores. Other diagrams show as PlantUML's own drawing. **UML** in the document bar switches to the source. Drawing a diagram needs PlantUML (and Java) installed on the computer and the desktop app. `!include` reads only from the file's folder (or the opened folder that holds it). In the document, N opens its Notes and ? shows the key hints; the editor's own notes and cheat sheet have their buttons.

## Chinese input

Type Chinese with pinyin in text boxes, the Notes panel, Ask AI, flashcard editors, quiz checks and Find, with no Chinese keyboard installed. Press **Ctrl Shift Space** while typing (or the **中** button in the text format bar and the Notes toolbar) to go Off → **Hanzi** → **Pinyin** → Off; right-click or long-press 中 for every choice, simplified or traditional characters, and **Chinese settings…** (also **View → Chinese input…**). Once Chinese mode has been turned on, the other fields get a small 中 at their right edge. Each note remembers the mode of its text boxes and of its notes; the other fields remember their own.

- **Pinyin**: tone numbers become marks as you type: `ni3hao3` → nǐhǎo, `Zhong1guo2` → Zhōngguó, `lv4` or `lu:4` → lǜ, `5` or `0` for the neutral tone. Works with no dictionary.
- **Hanzi**: type pinyin without tones (`nihao`, `wobuzhidao`); a menu at the caret lists characters with their pinyin above (coloured by tone) and their HSK level. **Space** writes the highlighted one (when released); **hold Space and press 1–9** to choose by number (Space+2 then Space+1 in one hold for a word in parts); **← →** or **Tab** move the highlight, **− =** or **Page Up / Down** turn the page, a click or tap chooses. A digit on its own right after pinyin gives the tone (`ma3` → 马 码…); after paging or moving the highlight, or 6–9, digits choose (Settings can make digits always choose). Choosing a shorter word keeps the rest to choose next; **Backspace** undoes that choice. **Enter** writes the letters as typed, or the pinyin with marks when the line already has marked pinyin (*Auto*; Settings: always letters or always marks); **Shift Enter** always writes the letters. **Esc** clears the pinyin without closing the text box. `, . ? ! : ; \` give ，。？！：；、 (Settings can turn this off). A capital letter at the start is pinyin too (`Ni` → 你; a name with no characters is written as typed with Space or Enter), keys typed right after clicking with Text are kept, and **Shift** pressed alone switches to Latin letters for a while (again to go back).
- On phones the candidates are a strip above the keyboard (▾ shows more rows). The mode needs a keyboard that types Latin letters; a keyboard that composes Chinese itself keeps working as before.
- The characters you choose move up the list, and a word built from several choices is learnt. **Settings → Chinese → Your words** exports and imports them.

**Dictionaries.** The common words and every HSK 1–3 word come with the app. **HSK 4, 5, 6 and 7–9** can be downloaded in Settings → Chinese → Dictionaries, kept on this device, and deleted any time.

*Dictionary data:* CC-CEDICT (https://cc-cedict.org/wiki/), © MDBG and contributors, CC BY-SA 4.0; word frequencies from FrequencyWords by Hermit Dave (OpenSubtitles 2018), CC BY-SA 4.0; HSK levels from complete-hsk-vocabulary by drkameleon (MIT). Converted and reduced for NoteComplete; the converted packs are available under the same licences.

## Reading Chinese

**Pinyin over characters.** **View → Pinyin over characters** shows the pinyin above Chinese in text boxes on the pages, the Notes preview, documents, flashcards and AI answers. It is a reading aid: the text stays as you typed it, and the readings come from the dictionary (as textbooks print them, without tone changes such as 不 before a fourth tone). A note with Chinese remembers whether it is on, and the last choice is what other notes start with. Tones are coloured (1 red, 2 orange, 3 green, 4 blue, neutral grey). In a tight box the pinyin can touch the line above; leave a little space between lines if it does.

**Ruby in Markdown.** Write `{汉字|hàn zì}` in the notes or any Markdown to put your own pinyin (or any reading) over characters, shown whether or not the automatic pinyin is on; tone numbers work too: `{你好|ni3 hao3}` shows nǐ hǎo. With as many syllables as characters each character gets its own; otherwise the reading goes over the whole group. `\{` writes a brace; nothing changes in code.

**Find** finds Chinese by its pinyin as well: `nihao` or `ni hao` finds 你好.

**Fonts and exports.** Chinese is shown in Noto Sans SC, which comes with the app and is loaded only for notes with Chinese, so it shows the same on every device, also where the system has no Chinese font. PDF, image and SVG exports carry the parts of the font the page needs, and the pinyin exactly when it is shown at the moment of exporting: the Export dialog's **Pinyin over Chinese** starts as the view shows it and can change it for that export. Long Chinese lines placed on a page by AI answers wrap between characters, never before a closing comma or full stop.

*Font:* Noto Sans SC, © Google LLC / Adobe, SIL Open Font License 1.1 (via Fontsource; its licence is shipped beside it, `vendor/fonts/noto-sans-sc/LICENSE`).

## Chinese stroke order

**Insert prefab → Languages → Stroke order** (or **Stroke sequence**) puts Chinese characters on the page with their strokes in order, pinyin above (tone numbers such as `ni3 hao3` become `nǐ hǎo`; with Chinese mode's dictionary it is filled in for you) and a 米字格 or 田字格 grid. Its window plays the strokes one by one like Hanzi Writer: **Space** plays or pauses, **← →** step a stroke, **Home / End** show none or all, the slider and the speed are below; with *reduced motion* set in the system, strokes appear without animating. The loop button beside the speed repeats every character; the small loop button over a character's corner picks just that one (accent: it repeats). **Still copy**, beside **Sheet**, shows the finished characters next to the animated ones (not offered when nothing animates). The window is also a look-up of the characters: under the player the pinyin (click a syllable to hear its tone), 🔊, ☆ favourite and HSK level; on the right, collapsible **Meanings** (a small scrolling box: click a meaning to put it on the page or take it off; the icons put back the first three, every one or none), **Forms**, **Structure** (radical, parts and how each character was made; click a part to trace it), **Words with it** and **On the page**. **Show this step on the page** puts the strokes drawn so far on the page (the last one in red, the rest as a grey outline); **Insert / Apply** keeps the figure's step. *Show* adds each stroke's number at its start, or the classic sequence (1, 1–2, 1–3…) beside each character. Right-click the figure for **Play…** and **Practise…**.

**Practise** has you write each character over its grey outline with the pen, a finger or the mouse, one stroke at a time; a stroke counts when it follows the right line in the right direction, and after two misses the stroke to write flashes in blue. Results (mistakes per stroke) are kept on this device for review.

Stroke data for the 3 000 most common characters ships with the app (loaded only when used); the other ≈ 6 500 are downloaded once from jsDelivr when first shown, checked, and kept for offline use. Characters without data show as plain text with "No stroke order for …". AI tools connected to the note server can insert the figure with `add_prefab` (`{"type":"hanzi","text":"你好"}`); the stroke data is added for them.

*Stroke-order data:* hanzi-writer-data 2.0.1 by David Chanin, derived from Make Me a Hanzi by Shaunak Kishore, based on fonts by Arphic Technology; licensed under the **Arphic Public License** (its text is shipped beside the data, `vendor/chinese/strokes/ARPHICPL.TXT`). The data is re-encoded (whitespace removed) and kept in separate files under that licence. Character frequencies used to choose the bundled 3 000: *FrequencyWords* by Hermit Dave (OpenSubtitles 2018), CC BY-SA 4.0.

## Looking up Chinese, converting, vocabulary cards

**Look up.** Right-click Chinese in a text box, a PDF or recognised page, the Notes, documents, flashcards or AI answers: **Look up 你好** (the word) and **Look up 好** (the character) come first in the menu. A finger held on a character opens it at once. With Chinese selected, the menu looks up the selection. **Chinese in a picture** (a scanned or image-only PDF, an inserted image) has no text to select: right-click a character and the menu opens as usual while a small snapshot around the pointer is read in the background (Chinese text recognition, its data downloaded once); within a second or so **Look up**, **Listen** and **Stroke order** for that character and its word appear at the top of the menu. This happens only once Chinese is in use on the device (its input mode was turned on, or the note has Chinese text). The panel (a window you can move; a sheet from the bottom on phones) shows the character large with every reading in tone colours (the one used in that place first), its HSK level and stroke count, 🔊 when the system has a Chinese voice, and the strokes playing in order (step, replay, **Practise** to write them). Below: the meanings for each reading, simplified / traditional / variant forms, the radical, the parts and how the character was formed, and up to 30 words with it. Any character or word shown there opens its own look-up; **←** goes back. In a text box, **Use here** next to another reading makes the pinyin over that character use it (it is kept in the note).

Buttons: **Copy** (the character, with pinyin, or the pinyin), **Flashcard** (into a new “Chinese vocabulary” deck or one of the note's decks: front 好, back `hǎo — good · HSK 1`), **Convert here** (that place only, to its traditional or simplified form), **Stroke figure** (inserts the stroke-order prefab on the current page) and **My words** (Chinese input offers it first).

**Translate, and Chinese selected anywhere.** Select Chinese (in a PDF with the Pan tool, a text box being typed, the Notes, documents, cards or AI answers) and a small bar appears beside it, as the Grab tool's: **Translate**, **Look up** (a word of up to 8 characters), **Stroke order** and **Listen**. Pinyin written out (`nǐ hǎo`, `ni3 hao3`) shows it too and is turned into characters first; pinyin shown over characters is left out of what you select. **Translate** opens a window with the sentence and its translation into Spanish or English (Google's free translator, MyMemory when that does not answer; it needs a connection, and each sentence is fetched once and remembered). **Colours** gives each word and the part of the translation that says it the same colour (the dictionary on this device and one more request; it stays on once chosen). Each word of the sentence opens its look-up. With the **Grab** tool, a region with Chinese (printed, typed or recognised) gets a **中** button that shows the same bar.

**es | en.** The look-up panel, the translation window and the stroke-order window have a two-sided **ES | EN** switch with a language icon: meanings and translations in Spanish or English. The dictionary is English; in Spanish its meanings are translated online (once, then remembered). One choice for every window; a stroke figure inserted while it is on ES gets its caption in Spanish.

**Right-click inside a text box you are typing** (Shift too) opens the panel of the character under the pointer, or of the Chinese you selected, and never removes the box; elsewhere in that box the usual text menu shows. **Shift + right-click on Chinese printed in a PDF** opens that character's panel instead of removing anything (Shift + right-click on an item still removes it).

**Convert to traditional or simplified.** Right-click a text box with Chinese → **Convert this text box (simplified ↔ traditional)…**, or select Chinese in a text box being typed or in the Notes and right-click. A preview shows the result; phrases decide most characters (头发 → 頭髮, 干部 → 幹部), and a character that could still be written more than one way is underlined: click it to choose. **Replace** changes the text; one undo brings it back.

**Vocabulary cards.** **Make vocabulary cards…** (a text box, a selection, a paragraph of the Notes or a document) lists every word once with its pinyin, meaning and HSK level; untick words, or turn levels off with the level chips, choose a deck and press **Make cards**. Decks with Chinese words get two extras: **Export to Anki…** asks for the layout (front and back; **pinyin as ruby** over the characters; **Anki furigana syntax** `你好[nǐhǎo]` for the `{{furigana:}}` filter; or **Chinese vocabulary** with three fields Hanzi / Pinyin / Meaning and the HSK level as a tag), and **Writing practice** has you write each character of the deck stroke by stroke (levels to practise as chips; characters with many mistakes come back once at the end).

## Handwriting from Markdown

**File → New from Markdown…** writes Markdown as real handwriting: pen and highlighter strokes on dotted, squared, ruled or blank paper, that you can erase, recolour and move here and in Noteful. **Pages → Insert handwritten pages…** adds such pages to the open note. The dialog shows a live preview; choose *Study notes* (titles, coloured sections, cards, columns, colour zones, sticky notes, diagrams) or *Plain notebook*, an ivory or black page, the handwriting, how neat it is, and a fineliner or a ballpoint with pressure. Opening a Markdown file first fills the dialog with it. The syntax (titles with `#`, `**term**`, `==highlight==`, `> [sky] CARD: text`, `!columns`, `!zone`, `!sticky`, `!stat`, SVG drawings with `!draw`) is listed in the dialog and in [AI agents](MCP.md#handwriting-markdown). Export the result as usual (PDF, images, `.noteful`). From a terminal, `noteful convert notes.md -o notes.noteful` does the same, and `--export pdf|png|svg` writes the pages directly.

## Audio

The headphones button next to Layers (**A**) opens the recordings in a side panel that resizes from its left edge, bottom edge or corner: play/pause (**K**), back and forward 10 s (**J**, **L**), seek, go to the page where the recording starts (**Shift+A**), dim ink not yet written at this point (**I**, off by default), and download the recording. The transcript follows the audio, and **Edit** lets you correct words while keeping their timing. Corrections are used by Find and the AI.

**Text from part of a recording.** The scissors in the audio panel (**Shift K**) choose a segment: drag the two handles on the position bar, type the start and end (m:ss), or set them at the playing position with the flags; ▶| plays just the segment. **Get text** gives only what is said in it: taken at once from the transcript when the whole recording was transcribed before, otherwise only that part of the audio is transcribed, with the engine, language and settings chosen under Transcript (much faster than the whole recording). The text can be copied, added to the notes beside the pages, or put in a text box on the page. The whole transcript and its saved copy are not changed.

The audio window keeps its controls on one row as it is resized: the space between them gives way first, then the buttons narrow; Record and Import show only their icons when it is narrow.

**Transcribe** offers the engines found on this computer:
- **Whisper on this device** (choose the model and language). Runs in the reader; the model downloads once.
- **Voxtype** (desktop app, when `voxtype` and `ffmpeg` are installed): local whisper.cpp, in 30-second pieces.
- **Gemini via Antigravity** (desktop app, when Antigravity is installed and signed in): ten-minute pieces, three at a time. The audio is sent to Google.

A transcript made earlier for the selected recording and engine appears on its own, with **Export**. **Revise with AI** (desktop app) lets your AI tool correct misheard words, terms and punctuation; every word keeps its time, and **Undo revision** brings back the automatic text. A quick local Voxtype pass followed by a revision is a good combination. Its menu also offers **Correct and flag likely noise**: recordings of a class pick up students talking among themselves, cut-off fragments and remarks unrelated to the lesson, and the AI underlines such stretches in red without removing anything. Click one to **Remove this phrase**, **Keep it** or listen to it first; the menu removes or keeps all flagged phrases at once. Whatever is left flagged is marked as likely noise when the transcript reaches the AI (explanations, summaries, quizzes, fact checks), and every AI request that includes a transcript is told that some of its phrases may be incoherent or irrelevant. The sliders button beside the dim-ink button holds gain, voice filter and normalize for transcription.

Text appears while it is transcribed, greyed until the timings are final. Transcription runs in the background with a chip in the bar: switching recordings or closing the panel does not stop it, only **Cancel** or the chip's Stop does. Export the transcript as text, SRT, WebVTT or JSON with word times.

## Find in a note

**Edit → Find…** (<kbd>Ctrl</kbd>/<kbd>⌘</kbd>+<kbd>F</kbd>, or type `find word` in the command palette) searches the open note's typed text, the text layer of its PDF pages, recognized text and recording transcripts. Matching ignores case and accents and accepts word beginnings (`memor` finds *memoria*). Recognized text and transcripts also accept one typing error in words of five letters or more, since recognition makes mistakes; for audio, try a couple of variants of the word. Enter/↓ and Shift+Enter/↑ step through matches, ☰ lists them by page with their source (Text, PDF, OCR, Audio), and highlights appear on the page. The source chips under the box limit the search to any combination of Text, PDF, OCR and Audio, with a count for each; the choice is remembered. Audio matches also seek the recording. The PDF text is indexed the first time you search a note and kept for next time.

**Batch OCR** in **Home → Recent** does the same for many documents at once, like **Batch transcribe**: select notes, PDFs and pictures (others are greyed out), choose languages and quality, and their pages are recognized one document after another in the background, without opening them; pages recognized before are skipped unless **Recognize again** is ticked.

**Share several notes at once.** **Share** in **Home → Recent** works like the batch modes: select notes (links and files inside archives are greyed out), then **Share (N notes)…**. The notes are sent as they are saved in Recent, with the device's share sheet (where the browser can share files), or packed in one .zip sent by **QR or link…** (the same Wi-Fi link, Web / iOS P2P QR and offline QR as *Share note via QR*), or saved with **Save .zip**. A received .zip opens in the archive window, where each note can be opened.

**Search inside notes.** The second magnifier beside **Search recent notes** (or **Shift Enter** in that box) makes the box search the text inside the documents of Recent instead of their names: PDF text, recognized handwriting and scans, typed text, handwriting written from Markdown, transcripts, and the text of Markdown and text files. Cards without a match are hidden and the matches are listed with their page; clicking one opens the note with Find on those words. A note opened once, recognized with Batch OCR or transcribed with Batch transcribe is searchable; for the rest, **Index…** reads their text in the background. Esc leaves the mode.

**Pages → Recognize text (OCR)…** reads handwriting and scanned pages so Find can search them. Handwriting is read in a separate pass over the ink alone, so it is found on PDF pages too, even when their printed text is skipped. It never runs on its own: choose the current page, a page range or the whole note, pick the languages (Spanish and English by default) and start it. It runs on this device, about 5–10 seconds per page; the language data (a few MB per language) downloads once on first use. Pages that already have a PDF text layer are skipped unless you untick that option. It then runs in the background with a chip in the bar (progress and **Stop**), so the dialog can close and you can keep reading. Results are kept with the note, and Stop keeps the pages finished so far. **Quality → High** reads each page more ways (larger, with thicker strokes, line by line and as scattered text) and lets the readings vote, a reading that is a real word counting double; it takes about twice as long. With **Quick result first** (ticked by default) every page is first read as Normal, so Find has its words at once, and then the remaining passes run and vote together with that first reading. If you stop it in between, pages keep the quick result; recognize them again with **Recognize again** ticked to improve them.

Misread words are corrected with word lists of the chosen languages (every language except Chinese; about 1–3 MB each, downloaded once: word frequencies from OpenSubtitles by Hermit Dave's *FrequencyWords*, CC BY-SA 4.0, and the *an-array-of-…-words* lists). A word that is a word of any chosen language is left alone, so English terms in Spanish notes stay as written. **Normal** only changes words that are not words: to the likeliest one a look-alike letter away (*procecador* → *procesador*, *e/* → *el*), and puts back an accent when the language writes the word only one way (*direccion* → *dirección*). **High** goes further, as a spelling checker does: for each word it weighs the reading, what the other passes read there, and words one or two changes away, by how common each is and how likely the change, so near-misses that happen to be rare words also become the word meant (*ce* → *se*, *Lempo* → *tiempo*, *trabjndo* → *trabajando*). A reading with an accent the engine saw, and acronyms, are kept. Find still finds every word as it was read. Chinese (simplified and traditional) is among the languages; Find matches it character by character, so a search for 学习 finds it wherever recognition split the line into words. Saving as `.notecomp`, `.notepart` or a project also writes them into the file, so the text comes with it to other devices and to AI tools connected to the note server (`page_text`, `search_note`). Recognition of handwriting is approximate.

**Tool row.** Drag the tool buttons to put them in the order you like; **View → Reset tool order** puts them back. The highlighter has three modes: straight, freehand and rectangle (drag a box).

**Notes in Markdown.** **View → Notes** (**N**) opens a panel beside the pages for your own notes in Markdown. Headings, bold, lists, code and links are formatted as you type; the toolbar above has the usual formatting buttons; **Preview** shows the result. **+ Page** inserts a page marker for the page you are reading: what follows belongs to that page, the marker jumps to it when clicked, and with **Follow** the notes scroll to the section of the page you turn to. Notes save themselves as you type (on this device, and in the project when you save it). **File → Export** has three buttons (hover for their full names): **NF** writes the .noteful file; **N+MD** writes it and a .md file with the page breaks spelled out; **NC** writes one .notecomp file with both, which NoteComplete opens with its notes (.notecomplete files open too).

**Ask AI answers** appear while they are written and are formatted (lists, tables, formulas). Under each answer, **T** puts its text in a text box on the current page, and **⧉** copies it. Drag the panel's top or bottom edge to change its height.

**Tabs (desktop).** Open several notes in one window: **+** in the top bar or **Ctrl+T** opens a tab, **Ctrl+Tab** switches, **Ctrl+W** or × closes (asking if there are unsaved changes), and tabs can be dragged to reorder. Each tab is independent.

**Page size.** **Pages → Page size…** changes the current page: extra writing space on the right or below, a standard size, the original size or a custom size in millimetres. Writing stays in place and the PDF keeps its size unless you choose to scale it to the new page. Undo restores the previous size. **Resize this page** changes the page in view; **Resize all pages** gives every page the chosen size in one step (extra space and Original follow each page's own size, so pages of different sizes each get theirs), and one Undo restores them all. **Pages → Resize by dragging the borders** does the same by hand: drag the handle on the right edge, the bottom edge or the corner; the size in millimetres follows the pointer. **Done** or **Esc** hides the handles.

**Text boxes.** The Text tool (**W**) types a text box where you click; Enter starts a new line, **Esc**, **Ctrl+Enter** or a click outside finishes; **Shift+Esc** or the **×** at the box's top-right corner discards it. A format bar above the box sets the font, size, bold, italic and colour while you type; select a typed box with Select to change them later, or double-click it to type. Click a box you typed to edit it (emptying it removes it); move or resize it with Select. Text boxes are searchable and are exported as Noteful text. **View → Text format bar in the tool bar** puts the format controls in the tool bar's settings row instead of a bar over the box; on narrow screens the floating bar wraps onto two rows to stay in the window.

**Math (LaTeX).** The **∑** button in the format bar makes the box a formula: type LaTeX (`\frac{a}{b}`, `x^2`, `\sqrt{x}`…) and it is typeset on the page, with a live preview under the box while you type. A box with no `$` is one formula; with `$…$` (inline) and `$$…$$` (display) parts, the rest is ordinary text (`Area: $\pi r^2$`); `\$` is a dollar sign. While a math box is typed, the **math keypad** shows at the bottom of the window: tabs for numbers and operations, functions, Greek letters, and calculus; each key writes its LaTeX with the cursor in the first empty place (a selection goes inside: select `x+1` and press √). **Tab** or the |→ key moves to the next empty place, Shift+Tab or ←| to the one before, ⌫ deletes. On phones and tablets the keypad replaces the system keyboard; the keyboard key brings that back for words. The **graph** key draws the box's function of *x* (`y = \sin x`, `f(x) = x^2 - 1`, `\frac{1}{x}`…) on axes under the box; an empty box gives empty axes. Math boxes move, resize, turn and lock like other text boxes. Noteful has no math, so a `.noteful` export keeps the LaTeX source as text; NoteComplete projects keep the formula.

**Editing a formula.** A box that is one formula is edited in place as a formula: tap any part (a numerator, an exponent) to change it, the arrow keys (or the keypad's ← → ↑ ↓) move through it, Backspace deletes whole pieces, and the keypad's keys put a fraction, a root or a power where the cursor is with places to fill. A box with words and `$…$` keeps its LaTeX as text, and the keypad's arrows step over whole commands.

**Graphs.** **Edit → Insert graph** (**Shift X**), the Shapes tool's **Graph** (drag its box), or the math keypad's graph key open the graph editor: one or more functions of x (each in its colour, typeset as you type), x from and to, y fitted to the curves or from and to, grid and numbers on or off, with a preview. An empty function list gives axes to draw on by hand. Select any part of a graph to move or resize the whole graph, **Edit graph…** to change it, or Delete to remove it; one undo brings back the graph as it was. It exports to Noteful as it looks. Functions can use powers, fractions, roots, `\sin`/`\cos`/`\tan` and their inverses, `e^x`, `\ln`, `\log`, `\log_b`, absolute values and implied products (`2x`, `x\sin x`); curves are cut at poles.

**Tables.** **Edit → Insert table** (**Shift Y**) or the Shapes tool's **Table** (drag its box) open the table editor: type in the cells, Tab and the arrows move between them, Enter goes down, and Tab in the last cell adds a row; the buttons add rows above or below and columns left or right of the cursor, or delete them; **Header row** makes the first row bold on a tinted band. `$…$` in a cell is math. Select the table to move or resize it, **Edit table…** to change the cells or add rows and columns. Graph and Table are also in the quick menu, with the other shapes.

**Bring to front, send to back.** Right-click an item (or use the ⋯ of a selection) and choose **Bring to front** or **Send to back**, or **Bring forward** and **Send backward** to move it past the next item it overlaps. With an item selected, **Ctrl ]** and **Ctrl [** move it one step, with **Shift** all the way. A group, a graph or a table goes to the front or the back as a whole; the Grab tool's bar has both for the items in its rectangle. Each change is one undo step and is kept in the project and in Noteful export (there, items that came from Noteful itself keep their first order).

**Lock in place.** The Lock tool (**O**) locks or unlocks the item you click. Locked items show a dashed outline and a padlock while the tool is chosen, and cannot be selected, moved or erased. Locks are undoable and saved in the project; on export an image's lock becomes Noteful's own (strokes and shapes keep theirs in the project only).

**Selecting text.** With the Pan tool, the cursor turns into a text cursor over printed PDF text and over recognized words; drag to select and press **Ctrl+C** to copy, line by line in reading order. Dragging anywhere else still moves the page.

## Share notes and draw on a tablet

In the desktop app, **File → Export and share… → Share live, or draw on a tablet…** starts sharing the note open in this tab with people and devices on the same network. Choose whether guests can edit the notes, only view them, or whether only drawing tablets join; **Start sharing** shows:

- **Drawing tablet**: a QR code, the computer's address and a 6-digit code (valid 10 minutes; **New PIN** (the circular arrow) makes another).
- **Notes invite**: a link (and its QR code) to send to people; the copy icon.
- **People**: who joined, with **Remove**.

The connection is meant for a trusted network (home, school): it is not encrypted, and the invite holds a secret. Coloured chips beside the note's name show who is connected; the first one is you (click it to change your name), and clicking someone scrolls the notes to their cursor. **Sharing** next to them reopens the dialog; **Stop sharing** ends the session for everyone. Closing the window while people are connected asks first: **Minimize** keeps the session running, **End session and close** ends it after everyone has saved.

**Handwriting from Markdown.** **File → New from Markdown…** and **Pages → Insert handwritten pages…** write Markdown as real handwriting ink, with a preview. The dialog has two tabs for how you start, and both fill the same Markdown box, so you can always edit the result before creating the note:
- **From Markdown**: type or paste your Markdown, or **Open a Markdown file…**. In the desktop app, **Make it richer with AI** has your AI tool rewrite it with highlights, cards, colours and drawings while keeping what it says.
- **From a prompt** (desktop app; **File → New note with AI…** opens here): describe the topic (“the cardiac cycle for a first-year exam”) or paste data, notes or a text, and press **Write the note** (Ctrl Enter). The Markdown and the preview fill in as it writes; **Stop** cancels.

Choose the AI tool and model under the tabs. When the AI has written the note, the dialog shows it under **From Markdown**, ready to edit or make richer. **Undo** and **Redo** above the Markdown step through its versions: each AI write, opened file and pause in your typing. Handwriting written this way keeps its text: Find searches it at once (as OCR) without recognizing anything, also after saving as a project or `.notecomp` file. A `.noteful` export does not carry it, so run **Recognize text** on such a file.

While a session runs, Share reads *Sharing* and opens it again, with the people's initials beside it (in every window size, phones included). In a browser or on a phone, Share offers the two ways to join.

**Use a phone or tablet as a drawing tablet.** Scan the QR code with the device's camera (the note opens in its browser), or in NoteComplete on the device choose **File → Join as drawing tablet…** and type the address and code. The device shows only the note and a tool bar: pen, highlighter, shapes (with their kinds and fill while Shapes is chosen), tape (strip or rectangle, with the tape's colours and widths while it is chosen), text, eraser, move, colours, widths, undo, redo, fit, **+** (a new blank page after the one in view, the same size), the ⇄ button that moves the bar to the other side, and disconnect. With Text, tap where the text goes: the keyboard opens and the box stays above it; tap elsewhere to finish, and the text goes to the computer. With Tape, drag across what to cover; tap a tape to lift or cover it on the tablet. Zoom and scroll it as you like: the computer keeps its own view and tools. While the stylus is in use, fingers move the page; two fingers scroll or zoom. What you draw appears on the computer as you draw, and is saved there with the note: save or export on the computer. Undo on the tablet undoes the note's last edit, whoever made it. Opening another note on the computer opens it on the tablet too.

**Write shared notes.** Open the invite link in a browser, or use **File → Join shared notes…** and paste it. Type your name (or keep *Guest N*) and press Enter or **OK**. Everyone's cursors show in the notes with their names; Ctrl Z undoes only your own typing. When the host ends the session, your copy of the notes is saved as a Markdown file and **Open my copy** opens it. If the connection drops, NoteComplete reconnects and your edits merge; if the host stays unreachable, your copy is saved the same way.

**People on other networks.** In the sharing dialog, **Turn on online access** gives a second link that works from anywhere, through a temporary Cloudflare address. The first time, NoteComplete downloads Cloudflare's small `cloudflared` program (checked before it runs). Online guests see the whole note live and draw on it only if you chose *Guests can edit*. A drawing tablet gets its own online link, so it does not need to be on your network. If phones on your Wi-Fi cannot open the local link on Linux, the sharing panel shows the firewall command that lets them in. **Turn off**, or stopping the session, ends it and disconnects the people who joined online. Cloudflare's free tunnels have no uptime guarantee.

**The device does not connect?**
- The device must be on the same Wi-Fi as the computer, and not on a guest network.
- If the computer also has a VPN, Docker or virtual machines, choose another address under the QR code.
- The computer must accept connections on TCP port 41237. It changes only when that port is taken.
  - On Windows, allow NoteComplete when the firewall asks.
  - On Fedora and other firewalld systems: `sudo firewall-cmd --add-port=41237/tcp`.
  - With ufw: `sudo ufw allow 41237/tcp`.

Not yet tried on real phones, tablets or styluses: see [Collaboration](COLLABORATION.md#not-yet-verified).

## Display quality

Open **☰ → Display quality**. Choose **Performance** (1×, 4 MP/page), **Balanced** (2×, 12 MP/page), or **Sharp** (3×, 20 MP/page, slightly stronger contrast). Adjust any slider to customize the preset:

- **PDF resolution**: raster pixels per displayed pixel on a 2× screen (tablets, phones, most laptops), from 1× to 3×. A 1× screen gets half as many per side, never fewer than it shows: Balanced draws at 1×, Sharp at 1.5×. Vector ink remains sharp independently.
- **Page pixel budget**: 4–24 megapixels per PDF page. This caps resolution on large pages to control memory.
- **Page contrast / brightness**: tune the page and preview appearance; the sample updates inside the dialog.

**Apply** saves locally and redraws nearby PDF pages only when resolution changes. **Cancel** or Escape discards changes. Presets also restore their brightness and contrast. Original image detail cannot be recovered by increasing resolution. Exported colors and document edits are unaffected; these preferences are not saved inside projects. Thumbnails remain small bitmaps to keep long notes responsive. On a slow device, start with Performance and collapse the transcript when unused.

## Draw and edit

**Touch** (phones, tablets and touchscreen computers):
- One finger does what the tool does: it draws, selects and moves, or scrolls with Pan.
- Two fingers scroll the page, or zoom when you spread or pinch them; a second finger cancels a stroke the first one had just begun.
- Tap with two fingers to undo, and with three fingers to redo.
- While a stylus is in use (it touched the page in the last 30 seconds), one finger scrolls the page with drawing tools too, as in drawing apps; put the stylus away and a finger draws again. The stylus draws with its pressure, and the line keeps the width it had while you drew it. Strokes are smoothed as you draw.
- Fingers and styluses never select the text on the pages; the mouse does.
- **Shift + wheel** scrolls fast; **Shift + arrows** or Page Up/Down scroll three times as far.
- Long menus scroll inside the window.

| Tool | Behavior |
|---|---|
| Pan | Drag with a mouse or scroll with touch. |
| Select | Select existing ink, supported shapes, images or text placement; drag to move, use four corners to resize (ink thickens or thins with the size, so a highlighter still covers what it covered), or the upper handle to rotate. The inspector changes dimensions/angle and ink/shape stroke color and width. |
| Pen | Freehand ink. With a stylus that reports pressure, pressing harder draws wider (about a third of the width when light, 1.7× when firm); a mouse or finger draws the chosen width. |
| Highlight | Straight segment by default; choose Freehand for sampled ink. Multiply at 50% preserves the appearance over images. |
| Erase (**B**) | Remove whole strokes and shapes (lines, rectangles, ellipses, triangles, arrows) the eraser touches; choose its size (small to extra large) in the tool settings. Other selected objects can be deleted with Select. |
| Image | Import PNG, JPEG or WebP onto the current page, then move or resize with Select. |
| Edit PDF (**E**, or its button beside the page list) | On a page from a PDF (a PDF you opened, or PDF pages in a note), the PDF's text shows as outlined blocks. **Double-click** a block and it becomes a text box in the same place, size, colour and line spacing, open for typing: in the PDF's own font when the PDF includes it and it has every letter, else the nearest of Sans, Serif or Mono. The PDF's copy of that text is gone from the page, and one undo puts it back. Scanned pages and PDFs whose letters are drawn as shapes have no text to edit. Bold, italic or coloured words inside a paragraph keep their style and font; while you type in the box it shows in one style, and the words come back as they were when you finish (new letters take the style of the letter before them). Changing bold, italic, the font or the colour from the format bar applies it to the whole box. Images, drawings (lines and shapes that touch), form fields and annotations are outlined in green: **double-click** one and it becomes a picture in its place, selected so you can drag, resize or delete it; the PDF behind no longer shows it. Drawings become pictures, not editable lines. |
| Shapes | Draw a bounding box or use Insert for a line, rectangle, ellipse, triangle, arrow or star. Rectangles, ellipses, triangles and stars can be filled: choose outline, tint (a pale fill in the pen colour) or solid in the shape settings, or press **F** to cycle. Resizing keeps the fill. In `.noteful` exports the fill becomes highlighter colouring under the outline. |
| Shapes from the pen | With the Pen, draw a line, arrow (shaft and head in one stroke), rectangle or square, ellipse or circle, triangle or star and **keep the pen still for a moment** before lifting: the stroke becomes a clean shape, in the pen's colour and width. Move before lifting to resize it; lift to keep it. Shapes drawn at an angle keep their angle. It is an ordinary shape afterwards (Select, corners, turning, fill; one undo removes it), and the pen stays the tool. In the Pen's settings choose **hold** (the default), **on lift** (clear, large shapes convert without holding; lines and letters stay handwriting) or **off**; **View → Shapes from the pen** turns it on or off too. |

Arrow keys on selection handles adjust geometry; Shift uses larger steps. Right-click an element on the page to remove it directly (a mouse only: a long press with a finger or pen never removes); Ctrl/Cmd Z restores it. **Shift + right-click** opens the quick menu instead. Undo/redo are global across pages (Ctrl/Cmd Z and Shift Z). Escape or a cancelled pointer gesture discards its unfinished preview. Separate shape fill-color editing is not currently provided. **Paste** (Ctrl V) puts a picture from another app on the page where the pointer is, selected; plain text becomes a text box there. **Ctrl B** hides or shows the notes panel and **Ctrl Alt B** the page list; a small tab on the window's edge brings back a hidden one. **Fonts:** the text format bar's font menu ends with **Import font…**: pick a TTF, OTF, WOFF or WOFF2 file and it is added to the menu on this device (kept in the browser's storage). Text in an imported font shows in it wherever that font is imported or installed; elsewhere the same kind of face is used.

**Colours by number.** With the Pen, Highlighter, Shapes or Tape, keys **1–9** choose the colour with that number in the tool settings (the number is written inside each colour circle); with a text box selected they choose its colour from the format bar. It is the same as clicking the colour, and the tool bar shows it. While you type in a text box or a field the digits are typed, Ctrl 1–9 still change tabs, and an open quiz or flashcards window keeps its own number keys. **?** shows the keys of the other buttons.

**Layers** selects where to draw, creates/renames layers, controls visibility/opacity and locks them. Hidden or locked layers cannot be edited. New strokes inherit the selected layer.


### Quick menu

**View → Tool bar** (**Shift + T**) hides the row of tools and their settings for more room; the quick menu has the same tools. Holding the × in the middle of the quick menu also shows or hides it. **View → Tool names in the tool bar** off shows the tools as icons only (their names are in the tooltips).

**Choose what the quick menu shows.** Hold any item of the quick menu without moving it (or right-click it) for its settings: **Change…** for a colour or a width, **Hide from this menu**, and the items hidden from that ring or row, to tap and show again. Each tool's settings have their own list, and it is remembered on this device; the tool bar is not changed. Graph and Table start hidden among the shapes, so the Shapes ring stays small; a crowded ring makes its items a little smaller rather than growing. The quick menu has the tool bar's options too: **Shapes from the pen** on the pen's ring (tap for the next of Hold, On lift and Off), **Any colour…** after each palette, the shapes' widths beside undo and redo, and **Lock in place** among the tools. Lock and the thinnest and thickest shape widths start hidden.

A ring of tools around your pen. Tap a tool to choose it, and its settings appear around it, always in the same places: colours across the top, left to right; sizes along the bottom, small to large; modes (highlighter, tape, shape fill, pen pressure) on the left; undo and redo on the right. Settings apply at once and the menu stays open. Hold a tool, a colour or a setting until it lifts and drag it to reorder; hold a colour without moving it, or right-click it, to change it with the colour picker. Widths work the same way, in the menu and in the tool bar: hold one (or right-click it) to set it in px, from 0.5 to 100. Everything is remembered, and each tool keeps the colour and width it was last used with.

To open it:

- **Keyboard and mouse**: hold **Shift + S**, point at an item and let go, or press **Shift + S** and click an item; or **Shift + right-click** on the page. **1–9** choose a tool, and **Esc** closes the menu.
- **Shift + pen**: hold Shift as the pen touches the page, or press Shift while the pen hovers over it. The menu opens at the pen, and nothing is drawn.
- **Pen side button**: on a computer, press a Wacom or Surface pen's barrel button on the page. On Android (Chrome, Brave), press the S Pen button while the pen **hovers** just above the page (if nothing happens, keep it held, lift the pen away and bring it back: Brave and Chrome often report the button only then), or **hold it and tap**; a press while the pen touches the screen does not reach web pages. **View → Pen button…** learns what your pen sends in this browser, can let a pen held still open the menu instead, or turns the button off. On Samsung devices, turn off *Open Air command with pen button* (Settings → Advanced features → S Pen → Air command). **Help → Test pen and stylus** shows what the pen reports. [Details](S-PEN-BUTTON.md).
- **Touch screens and iPad**: hold two fingers still on the page for half a second.

The Apple Pencil Pro squeeze and the Pencil double-tap are not available to web pages in Safari, so on iPad use the two-finger hold.

## Audio details

Nonempty recording names are shown unchanged; otherwise the UI generates a recording number and date. Dimming shows strokes at 20% opacity before they were written and normally afterwards; seeking backwards restores dimming. This is whole-stroke timing, not point-by-point replay, and untimed ink remains visible. Each recording keeps its own playback position. Codec support varies by browser and device; **Download** remains available when playback is unsupported.

### On-device transcripts

With **Whisper on this device**, Whisper runs in a local WASM worker and detects
the spoken language when **Detect language** is selected. A progress bar shows
the model download and each transcription chunk while it runs. Castellano is the
default, with Galego and English available alongside other language options.
The model list offers Tiny (fastest), Base (default) or
Small (higher accuracy, more memory). Under **Audio for transcription**, gain and the voice filter affect playback
and transcription; normalization applies to transcription only. Processing never
overwrites the original recording. Changes take effect on the next transcription.
The cache distinguishes the model, language and audio settings.
The first run downloads model weights from Hugging Face; Whisper never uploads audio (only the Gemini engine does).
Downloaded weights are browser-cached when storage is available.

Words follow playback and clicking a word seeks the same clock used for timed
handwriting. Ink synchronization requires the note's original recording timestamps.
With **Pan** selected, click a timed stroke to seek its recording; dragging still
scrolls the page. The correct recording is selected automatically.
Automatic transcription and word boundaries can be inaccurate, especially for
noise or quiet speech. Processing speed and memory depend on the device.

Transcripts are cached by audio content in this browser on secure origins
(including localhost), separately for each engine.
They are not included in `.nfedit` or `.noteful` exports. On LAN HTTP without
SubtleCrypto, transcripts remain available for the session and can be exported.
Long transcripts display
100 words at a time, with section arrows and optional automatic following. Hidden
transcripts perform no word highlight updates. Speech workers terminate after
completion or cancellation; page thumbnails retain small bitmaps only.

## Save and export

- **Save project .nfedit** keeps unchanged source bytes, edits and undo/redo history.
- **Export .noteful** flattens applied edits into a new native archive; see [writer limitations](../spec/nfedit-v1.md#native-export).
- **Export page SVG** includes the rendered PDF background and current layers/audio appearance. Wait for the PDF page to finish rendering.

**Where Save (Ctrl S, the floppy disk) puts a note.** The same note always goes back to the same place, and Recent on Home always opens what you last saved:

- **Desktop app:** a note opened from a file is saved over that file (only in the same format: a `.noteful` saved as a project asks where to put the `.nfedit`). A new note asks once where to save it; the chosen file joins Recent and later saves go over it. A name typed without an extension gets the right one.
- **Website and phone app:** a new note, or one opened from Drive, is kept in NoteComplete on this device (the folder chosen on Home, or this browser's storage) and appears in Recent; later saves update that copy. A file you opened or that was shared with you is kept the same way, and saving updates its copy in Recent (saved as a project, the copy becomes the `.nfedit`). Opening the original file again afterwards adds it beside your edited copy instead of replacing it. To get a file to keep or send elsewhere, use **File → Export**.

Exports download as new files; originals are not overwritten. Replacing a dirty document prompts before discarding edits. Native export does not mark the richer project as saved. Fonts resolve from the device; Apple fonts are not bundled. Exact native ink smoothing, advanced text layout and some object variants remain incomplete.


### Auto-save

**File → Auto-save** (on by default) copies the open note every minute, while it has changed, into automatic slots on this device. It also makes a copy when you switch away from the app or close it. Copies never go over the file you saved, and each note keeps its last five.

- **File** lists this note's automatic saves; **All automatic saves…** lists every note's, to open or delete them.
- Opening a note with an automatic save newer than your last save asks which to open: the **automatic save** or the **manual save** (the file). An automatic save opens as an unsaved copy; save it to keep it.
- In a sharing session the **host's** switch applies to everyone: guests and tablets show it, locked. A guest or tablet that loses the session, or sees it end, keeps an automatic save of the note and is offered to open it.
- Automatic saves are complete projects (the original note plus every edit, with undo history and the Markdown notes). They live in this browser's storage, so clearing site data removes them.
- **Deleting the history.** A project (`.nfedit`) keeps every edit so it can undo, and grows with them. In **File**, ✂ beside an automatic save deletes the history up to that save, and **Delete history up to now** deletes all of it. The note stays exactly as it is: strokes, pictures and text drawn and later erased go, with all their edits, as do moves superseded by later ones and what was undone; the file is smaller once saved. You can no longer undo past that point; edits after it still undo. ✂ appears beside saves made from version 1.1.31 on that are still part of the note's history as it is now (not after deleting the history up to a later point). It is not available while sharing, since every copy of the note keeps the same history. The engine checks that every page still draws the same before changing anything.

## Mobile and Android file opening

The Expo wrapper uses SDK 57 and the same browser/WASM engine. Install dependencies and start it as shown in the [README](../README.md#expo-go). The launcher serves web assets on LAN port 8768 and Metro on 8081. It does not serve the original corpus. Files selected on the phone are not uploaded. A Metro tunnel alone does not expose the separate reader server.

Use an Expo Go client compatible with the SDK 57 dependencies pinned in this repository. See [mobile setup](../README.md#expo-go).

Installed Android builds include the reader and serve it on the device's loopback address, so no hosted website or computer is needed. To use a hosted reader instead, set `EXPO_PUBLIC_READER_URL` before starting or building the wrapper. The browser reader can also be installed to the home screen over HTTPS. Its application cache supports offline use after assets have been cached; opened notes are never stored in that cache.

Saving a note keeps it in the app and in Recent (see [Save and export](#save-and-export)). Exports in the wrapper open the OS share sheet. Select Save to Files or another destination. Dismissing a share sheet does not prove a file was saved, so unsaved-change protection remains active. Large exports temporarily require base64 copies in memory; there is no fixed MB ceiling.

Android default-file handling requires an installed NoteComplete build. Expo Go cannot register this project's own file associations. See the Android build instructions below; default selection remains an Android/user decision. Physical-device URI permissions, file-manager behavior, codecs and sharing require device validation.

### Android installed build

The Android app ID is `com.notecomplete.viewer`. Its manifest registers ACTION_VIEW (file and content URIs) and ACTION_SEND / SEND_MULTIPLE for the MIME types of every supported file (see [Opening files from the system](#opening-files-from-the-system)), plus `.noteful`, `.nfedit`, `.notecomp`, `.notecomplete` and `.notepart` paths as `application/octet-stream`, any type or none, since Android rarely knows those extensions. A generic `application/octet-stream` content-provider filter remains for providers that hide the filename; it can also offer NoteComplete for other binary files, which the reader rejects if unsupported. Some file managers use other MIME types or do not offer persistent defaults.

For local builds or GitHub Actions APK artifacts, follow [Installable builds](BUILDS.md#android-apk). That guide covers the bundled reader, the optional hosted-reader override, preview signing and build prerequisites.

**Beta builds from a branch (Linux desktop app).** **Help → Check for updates (branch)…** builds a branch of the GitHub repository on this computer and installs it, to try changes before they are released: pick or type the branch, then **Build and install**. The first build takes a while; NoteComplete stays usable meanwhile and the top bar shows how far it got. Nothing is replaced unless the build succeeds, the copy you had is kept as `NoteComplete.AppImage.previous`, and **Back to the latest release** returns to the normal releases. It needs git, Rust (cargo), Node.js, Python 3.11+ and squashfs-tools installed (the dialog names what is missing). See [Installable builds](BUILDS.md#updates).

**Updates on Android.** **Help → Check for updates…** compares this app with the newest release on GitHub, and with **Check for updates when NoteComplete opens** on it looks by itself shortly after the app opens. When there is a newer version, **Download** opens its APK in the browser: open the download to install it over this app (Android asks to allow installing from the browser the first time). Copies from before 1.1.41 cannot check: install 1.1.41 once by hand.

In Android Files, choose a supported file, select **Open with → NoteComplete**, then **Always** if offered. Android controls that choice; the application cannot silently make itself the default. A running app receives new file and share intents too. The app asks the provider for the file's display name and type, reads it using the provider's URI grant, queues it until the reader is ready, and passes it on under its real name; only a missing extension is filled in, from the MIME type or the file's bytes. Existing unsaved edits still require confirmation before replacement.

Manifest generation and JavaScript bridge tests are validated. No Android SDK/device was available on the development host for APK compilation or an actual default-handler test. Physical-device validation is still required, particularly with opaque `content://` URIs and different file managers.

**Import, export and share.** **File → Import…** is the one place to bring things in: pick any file and NoteComplete decides what it is: study material from another NoteComplete (.ncstudy), a quiz from Quiz Toolkit (Markdown, with its pictures: they show with the question and cost no points), a flashcard deck (JSON) or a note or document to open. **File → Export and share…** is the one place to send things out: pages as PDF, image or SVG; the note as a NoteComplete, project, Noteful or Noteful + Markdown file; flashcards and quizzes to Anki; and sharing with others (send or receive study material, share live, join someone's notes, use a device as a drawing tablet). In this window **Tab** and **Shift Tab** go round Open & Import, Export → Notes and Export → Resources; **1–9** choose the item with that number on its key (arrow keys move between items, Enter chooses) and **Esc** closes it. Export always opens on Notes.

## Office suite module (Euro-Office)

NoteComplete can open Word, Excel and PowerPoint files either in its built-in **Text view (Markdown)** (read-only) or in the optional **Euro-Office** module (full local editor, AGPL-3.0-only + CC BY-SA 4.0, downloaded separately on the desktop app from **Help → Setup wizard → Modules**; ~1 GB download, ~3.2 GB on disk). It starts on demand on `127.0.0.1` when you open a file in Euro-Office and stops automatically after ~10 minutes idle or when NoteComplete quits.

- **Linux (x86_64 & ARM64):** uses Podman or Docker when available without `sudo`, or NoteComplete's built-in rootless runner (`unshare --map-auto` + `pasta` from the `passt` package + `newuidmap`). On Ubuntu 24.04+ where AppArmor restricts unprivileged user namespaces, install Podman/Docker or allow user namespaces (`sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`).
- **Windows (x64):** installs the official Linux image into a dedicated WSL2 distribution (`NoteComplete-EuroOffice`) — no Docker Desktop required. Enabling WSL2 asks for administrator permission once and may require a restart. *(Not yet verified on a real Windows machine.)*
- **macOS (Apple Silicon):** runs the official ARM64 image through whichever container runtime is installed (Apple `container` on macOS 26+, Podman, Docker Desktop, OrbStack, or Colima). *(Not yet verified on a real macOS machine.)*
- **Web reader:** Euro-Office requires the desktop app; office files continue to open in NoteComplete's text view.
